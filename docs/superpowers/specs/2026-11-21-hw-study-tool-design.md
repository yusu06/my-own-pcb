- 상태: 승인됨 (2026-11-22)

## 1. 의도와 이유

대상은 전자공학 입문자다. 아는 것은 간단한 논리 게이트와 기초 전기 용어 정도다.
목표는 **클라이언트가 원하는 기기(회로 설계·PCB 의뢰)를 만들어 줄 수 있는 프리랜서 하드웨어 엔지니어 실력**을 갖추는 것이다.
앞으로 PC 없이 지내는 기간이 길어서 **폰으로, 짧은 시간에, 인터넷 없이도** 공부할 수 있어야 한다.

영감은 Steam 게임 "IT THINKS: Build Your Own GPU"에서 얻었다. 이 게임은 NAND 게이트에서 출발해 칩을 만들고 테스트 벤치로 검증하는 퍼즐 게임이다.
가져오는 것은 **장르의 방식** 세 가지다: 직접 회로를 만든다 → 자동 테스트로 검증한다 → 만든 부품을 다음 단계에서 재사용한다.
GPU라는 주제는 사용자에게 중요하지 않다. 대신 **"이 회로가 실제 어떤 기기에 어떻게 쓰이는가"**가 핵심이다.

## 2. 목표 / 비목표 / 실패 조건

### 목표
- 모든 단원은 **실제 기기 클라이언트 의뢰서**로 시작하고, **"실제 기기에서는"** 설명으로 끝난다.
- 입문자 눈높이에 맞춘다. 새 용어는 처음 나올 때 탭하면 한 줄 설명이 뜬다.
- 한 단원은 5~20분 분량이다(자투리 시간 기준).
- 폰 세로 화면 우선, 터치 조작, 첫 접속 이후 완전 오프라인 동작.
- 회로 그리기와 Verilog 모두 **자동 채점**한다.
- 단원 내용(텍스트·문제)은 코드와 분리해 쉽게 추가·수정한다.

### 비목표 (하지 않는 것)
- IT THINKS의 레벨, 그래픽, 문구, 이름을 복제하지 않는다. 게임 파일도 분석하지 않는다. 내용은 모두 교과 지식으로 새로 쓴다.
- 전체 Verilog 문법을 지원하지 않는다(부분집합만 지원, §6.3).
- SPICE 수준의 정밀한 아날로그 시뮬레이션은 하지 않는다.
- PCB 배치·배선 편집기는 만들지 않는다. 6장은 퀴즈와 리뷰 문제로 다루고, 실습은 PC의 KiCad로 안내한다.
- 계정, 서버, 랭킹, 멀티플레이는 없다.
- 1차 목표(0~2장)에 MCU 시뮬레이터는 포함하지 않는다.

### 실패 조건 (동작해도 실패로 본다)
- 실습에 인터넷이나 PC가 필요한 경우(0~2장 기준).
- 틀린 회로가 채점을 통과하거나, 맞는 회로가 떨어지는 경우.
- 기술적으로 틀린 내용을 가르치는 경우.
- 설명 없이 전문 용어가 나와 입문자가 막히는 경우.
- 폰에서 선 연결이 답답해서 공부를 포기하게 되는 경우.

## 3. 제약
- 대상 기기: 사용자의 스마트폰(안드로이드·아이폰 모두 고려). 최신 모바일 Chrome과 Safari에서 동작해야 한다.
- 오프라인: 서비스 워커로 앱 전체를 미리 캐시한다. 첫 접속에만 인터넷이 필요하다.
- 저장: 기기 안(브라우저 저장소)에만 저장한다. 폰 교체·초기화에 대비해 백업 파일 내보내기/불러오기를 제공한다.
- 비용 0원: 무료 호스팅을 쓰고 유료 의존성은 쓰지 않는다.
- 일정: 2027년 초까지 약 10주. **그때까지 0~1장을 검증까지 마쳐 완성하는 것이 최우선**이다. 2장은 그 전에 최대한 진행하고, 남은 부분은 이후 업데이트로 추가한다(사용자 결정).
- 업데이트: 그 이후에도 틈틈이 업데이트를 배포한다. 따라서 업데이트가 저장된 진행 상황과 부품을 절대 깨뜨리면 안 된다(§6.7).

## 4. 접근 방식 (검토한 안)

| 안 | 내용 | 장점 | 단점 | 결정 |
|---|---|---|---|---|
| A. 직접 만드는 PWA | 웹앱 + 직접 만든 시뮬레이터 3종 | 오프라인, 폰 UX, 자동 채점, 하나로 통합 | 만들 양이 많음, Verilog는 부분집합 | **채택** |
| B. 기존 도구 묶기 | 단원 설명 + Falstad/HDLBits/Wokwi 링크 | 빠르고 정확 | 인터넷 필수, 자체 채점 불가, 폰 UX 불량, 외부 의존 | 탈락 (오프라인 조건 위반) |
| C. 네이티브 앱 | Flutter 등 | 터치 UX 최고 | 개발 환경이 무겁고 플랫폼에 묶임, 이득 대비 비용 큼 | 탈락 |

사용자는 A를 선택했다. 이유: "폰으로, 인터넷 없이, 자동 채점까지"라는 조건을 A만 모두 만족한다.

## 5. 커리큘럼 (사용자 확정)

모든 단원은 **의뢰서 → 개념 카드 → 실습 → 실제 기기에서는 → 퀴즈 2~3문제** 순서로 진행한다.

- **0장. 스위치에서 게이트까지** (7): 0-1 손전등(닫힌 회로) · 0-2 손전등 v2(LED 저항, V=IR) · 0-3 자동차 실내등(병렬=OR) · 0-4 전자레인지 쉬운 판(직렬=AND) · 0-5 냉장고 실내등(NOT) · 0-6 1과 0의 정체(전압 → 게이트 기호) · 0-7 전기로 누르는 스위치(트랜지스터 맛보기)
- **1장. 조합 논리** (11): 1-1 전자레인지 인터록(NAND 만능) · 1-2 계단 조명(XOR) · 1-3 금고 경보기(진리표→식) · 1-4 부품 줄이기(불 대수) · 1-5 첫 Verilog(`assign`, 이후 그리기와 병행) · 1-6 엘리베이터 층 표시(7세그 디코더) · 1-7 조이스틱 방향(인코더) · 1-8 TV 입력 선택(MUX) · 1-9 간이 계산기(반/전가산기) · 1-10 계산기 v2(4비트 덧셈·뺄셈) · 1-11 보일러 온도 설정(비교기)
- **2장. 순차 논리** (12): 2-1 토글 전등(래치) · 2-2 클럭 · 2-3 D 플립플롭(`always`) · 2-4 버튼 두 번 눌림(디바운싱) · 2-5 레지스터 · 2-6 전자레인지 타이머(카운터) · 2-7 1초 만들기(분주기) · 2-8 LED 전광판(시프트 레지스터) · 2-9 신호등(FSM) · 2-10 도어락(FSM) · 2-11 자판기(FSM) · 2-12 전자레인지 완성(종합)
- **3장. 작은 컴퓨터** (7): 메모리 → ALU → 명령어 → 프로그램 카운터 → 4비트 CPU → 장난감 로봇 프로그램 → "왜 MCU인가" (설계: 2026-11-23-ch3-small-computer-design.md)
- **4장. 아날로그와 전원** (11): 볼륨 노브(분압기) · 아날로그 스틱 · 풀업/풀다운 · 자동 야간등(CdS) · 딜레이 램프(RC) · 역전압 보호(다이오드) · 미니 선풍기(트랜지스터 모터 구동) · 릴레이 · USB 기기(레귤레이터) · 온도계(서미스터) · 전력과 정격
- **5장. MCU와 펌웨어** (11): GPIO 출력/입력 · ADC · PWM · 타이머·인터럽트 · UART · I2C · SPI · 전자레인지 MCU판 · 게임패드 · 저전력
- **6장. PCB와 실무** (10): 회로도 읽기 · 데이터시트 · 부품 선정·BOM·원가 · 풋프린트 · 배선 폭 · 디커플링 · 접지 · 제조 주문(Gerber) · 납땜·멀티미터 · 의뢰 받는 법(요구사항·견적·일정)
- **7장. 종합 의뢰** (4): USB 게임패드 · 도어락 · 스마트 화분 · 전자레인지 제어보드

**1차 범위(마일스톤 1~5):** 0~2장 전체, 즉 30단원. 3장 이후는 1차 완성 뒤 별도로 설계한다.

### 5.1 단원별 과제 유형 (Claude가 정함)
원칙: 폰에서 게이트를 하나씩 그리기 버거운 크기가 되면 Verilog가 주 과제가 된다. 이때 그리기 과제는 이미 만든 부품을 블록으로 조립하는 수준으로만 낸다.

| 단원 | 과제 |
|---|---|
| 0-1 ~ 0-5, 0-7 | 전기 회로 |
| 0-6 | 전기 회로 → 같은 동작을 게이트 기호로 다시 그리기 |
| 1-1 ~ 1-4 | 논리 그리기만 (게이트 10개 이하) |
| 1-5 | 그리기(1-1 회로 재사용) + Verilog |
| 1-7, 1-8, 1-9, 1-11, 2-1, 2-3, 2-5 | 그리기 + Verilog |
| 1-6, 1-10, 2-6, 2-7, 2-8 | Verilog 주 과제 + 부품함 블록을 조립하는 짧은 그리기 |
| 2-2 | 퀴즈 + 클럭 타임라인 관찰 (채점은 퀴즈) |
| 2-4, 2-9 ~ 2-12 | Verilog만 (FSM은 상태도 그림을 개념 카드로 제공) |

편집기 화면 하나에는 부품 약 30개까지를 목표로 한다. 그보다 큰 회로는 계층(부품함 블록)으로 나눈다.

## 6. 구조

### 6.3 시뮬레이터

**디지털 논리 시뮬레이터 (`sim/digital`)**
- 게이트 수준의 넷리스트를 시뮬레이션한다. 기본 부품: NAND, 입력(스위치/버튼), 출력(LED/7세그먼트), 클럭, 상수 0/1.
- 그 밖의 게이트(NOT·AND·OR·XOR 등)는 사용자가 단원에서 직접 만들어 **부품함에 저장한 커스텀 부품**으로 쓴다. 해금된 기본 게이트를 쓸지는 단원 데이터에서 정한다.
- 커스텀 부품은 계층 구조로 저장하고, 시뮬레이션할 때 펼친다(flatten).
- 신호값은 0, 1, X(연결 안 됨 또는 미정) 세 가지다. 연결 안 된 입력은 X로 표시해 초보자가 실수를 바로 알아보게 한다.
- 래치(2-1)를 위해 피드백 루프를 허용한다. 단위 지연 이벤트 방식으로 반복 계산해 안정될 때까지 돌리고, 일정 횟수 안에 안정되지 않으면 "발진" 오류로 알린다.
- 2-3 이후에는 D 플립플롭을 기본 부품으로 해금할 수 있다(단원 데이터에서 지정).
- 점수: NAND 환산 개수(커스텀 부품은 내부 NAND 수를 합산)를 "부품 원가"로 표시한다.
- 원가 목표(Claude가 정함): 과제에 `maxCost`를 줄 수 있다. 1-4처럼 목표가 핵심인 단원은 통과 조건으로 쓰고(`costRequired: true`), 다른 단원에서는 달성하면 ⭐만 준다. 모범 답안은 목표를 만족해야 하고, 목표를 넘는 오답 하나를 테스트에 넣는다.
- 2-4 디바운싱(Claude가 정함): 앱의 클럭 한 칸을 "1ms"로 정의한다. 테스트 벤치가 버튼 입력을 여러 칸 동안 빠르게 0/1로 튀게 하는 각본(바운스 각본)을 넣고, 출력이 한 번만 바뀌는지 확인한다. 실제 바운스 시간(수 ms, 스위치마다 다름)과 RC 하드웨어 디바운스는 개념 카드에서 설명하고, RC 방식은 4장에서 다시 다룬다.

**Verilog 해석기 (`sim/verilog`)**
- 지원 문법:
  - `module`/`endmodule`, ANSI 스타일 포트 선언(`input`/`output`/`output reg`, 벡터 `[n:0]`), `wire`, `reg`, `localparam`
  - `assign`, `always @(*)`, `always @(posedge clk)`(필요하면 `or posedge rst`), `begin`/`end`, `if`/`else`, `case`/`endcase`/`default`
  - 블로킹 대입(`=`)과 논블로킹 대입(`<=`)
  - 연산자: `~ & | ^ ! && || == != < <= > >= + - << >> ?:`, 비트 선택 `a[3]`, 범위 선택 `a[3:0]`, 연결 `{}`, 리터럴 `4'b1010`, `8'd5`, `8'hFF`, 10진수
  - 같은 파일 안의 모듈 인스턴스(이름 지정 포트 연결 `.a(x)`)
- 지원하지 않는 문법: `initial`, `#지연`, `$display` 같은 시스템 태스크, `generate`, `function`/`task`, 4값 논리의 z, signed. 이런 문법을 쓰면 "이 앱에서는 아직 지원하지 않아요"라고 안내한다.
- 의미: 조합 로직은 안정될 때까지 반복 계산한다. 클럭 상승 에지에서는 `posedge` 블록을 모두 평가하되, 논블로킹 대입은 모아 두었다가 한꺼번에 반영한다.
- 테스트 벤치는 앱이 제공한다. 사용자는 모듈만 작성한다.
- 오류 메시지는 한국어 초보자용으로, 줄 번호와 고칠 힌트를 함께 보여준다. 예: "3번째 줄: 세미콜론(;)이 빠졌어요."

**전기 회로 해석기 (`sim/electric`)**
- 직류(DC) 해석: 수정 절점 해석법(MNA)으로 선형 연립방정식을 푼다.
- 부품: 전지(전압원 + 작은 내부저항), 저항, 스위치/버튼(닫힘 ≈ 0.01Ω, 열림 = 끊김, 평상시 열림·닫힘 두 종류), 전구(저항), LED와 다이오드(구간 선형 모델: 순방향 전압 Vf + 작은 저항, 역방향이면 끊김. 상태를 바꿔 가며 반복 계산).
- 0-7용 트랜지스터는 단순 스위치 모델로 둔다(베이스 전류가 있으면 컬렉터–이미터가 닫힘). 정확한 모델은 4장에서 다룬다.
- 결과 표시: LED 밝기는 전류에 비례하고, 선 위로 전류 흐름 애니메이션을 보여준다. 정격 전류(예: 표준 LED 20mA)를 넘으면 "LED가 탔어요" 연출을 한다. 탭하면 각 노드 전압과 부품 전류를 볼 수 있다.
- 4장의 커패시터 과도 해석(후진 오일러)은 같은 구조를 확장해서 넣되, 1차 범위에는 포함하지 않는다.

### 6.4 단원 데이터 형식
단원은 TypeScript 객체로 작성한다(`src/lessons/ch0/0-1-flashlight.ts`). 타입 검사로 형식 오류를 빌드 때 잡기 위해서다.

```ts
interface Lesson {
  id: string;               // "0-1"
  chapter: number;
  title: string;            // "손전등"
  minutes: number;          // 예상 소요 시간
  client: { from: string; request: string; requirements: string[] };
  concepts: Card[];         // 개념 카드 (짧은 본문 + 선택적 그림)
  tasks: Task[];            // 실습 과제 (1개 이상)
  realWorld: Card[];        // "실제 기기에서는"
  quiz: QuizItem[];         // 2~3문제
  unlocks?: string[];       // 이 단원을 마치면 해금되는 부품
  glossary?: string[];      // 이 단원에서 처음 나오는 용어 id
}

type Task =
  | { kind: "electric"; parts: PartKind[]; checks: ElectricCheck[]; reference: Circuit }
  | { kind: "logic"; parts: PartRef[]; io: IOSpec; tests: TestSpec; reference: Circuit; saveAs?: string;
      maxCost?: number; costRequired?: boolean }
  | { kind: "verilog"; skeleton: string; io: IOSpec; tests: TestSpec; reference: string };
```

- `ElectricCheck` 예: "스위치 상태별로 LED가 켜지는지/꺼지는지", "LED 전류가 5~20mA 범위인지", "단락 금지".
- `TestSpec`: 조합 회로는 진리표 전체를 자동 생성하거나 직접 지정한다. 순차 회로는 클럭 단계별로 (입력, 기대 출력)을 나열한다. 화면에 보여줄 테스트와 숨겨진 테스트를 둘 다 지원한다.
- `reference`: 모범 답안. 사용자에게 보여주지 않으며, 아래 §8의 자동 검증에만 쓴다.
- 퀴즈 유형: 객관식, 숫자 입력(허용 오차 포함). 문제마다 해설을 단다.

### 6.5 화면과 조작 (폰 세로 기준)
- **홈**: 장별 지도와 단원 진행 상태(잠김/진행 중/완료, NAND 점수). 다음 할 단원으로 바로 가는 버튼.
- **단원 진행**: 의뢰서 → 개념 카드(좌우 넘기기) → 실습 → 실제 기기에서는 → 퀴즈 → 완료. 중간에 나가도 그 자리에서 이어서 한다.
- **회로 편집기**:
  - 아래쪽 팔레트에서 부품을 탭해 놓고, 드래그로 옮긴다. 격자에 맞춰 붙는다.
  - **선 연결은 "핀 탭 → 다른 핀 탭"** 방식이다(드래그보다 폰에서 정확함). 선 경로는 자동으로 직각으로 그린다.
  - 두 손가락으로 확대·이동한다. 길게 누르면 메뉴(삭제·회전)가 뜬다. 실행 취소/다시 실행을 지원한다.
  - 시뮬레이션은 항상 켜져 있다. 입력 스위치를 탭하면 결과가 바로 바뀐다.
  - "테스트 실행" 버튼을 누르면 진리표나 타임라인이 나오고 틀린 줄이 빨갛게 표시된다.
- **Verilog 편집기**: 고정폭 글꼴, 줄 번호, 키보드 위에 기호 버튼 줄(`; & | ^ ~ ( ) [ ] { } <= begin end`)을 둔다.
- **용어집**: 본문의 밑줄 친 용어를 탭하면 한 줄 설명 팝업이 뜨고, 전체 목록 화면도 있다.
- **설정**: 백업 내보내기/불러오기(JSON 파일), 라이트/다크 테마, 진행 초기화.
- 모든 문구는 한국어로 쓴다. 코드와 식별자는 영어 그대로 둔다.

### 6.6 진행 규칙과 부품함 (Claude가 정함)
- 단원은 순서대로 해금하는 것을 권장하지만 **건너뛰기를 허용한다**. 혼자 공부하다 막혔을 때 도와줄 사람도 인터넷도 없을 수 있기 때문이다. 건너뛴 단원은 홈에서 "건너뜀"으로 표시한다.
- 단원을 건너뛰었거나 부품이 사라져서 필요한 부품이 부품함에 없으면, 그 단원의 모범 답안으로 만든 **기본 부품**을 대신 쓴다(회색 표시, 원가에 정상 반영). 다음 단원이 막히지 않게 하려는 장치다.
- 부품을 수정하면 **새 버전**으로 저장한다. 그 부품을 이미 사용한 회로는 저장 당시 버전을 그대로 유지한다(스냅샷). 최신 버전으로 바꾸는 것은 사용자가 직접 선택한다.

### 6.7 저장
- 진행 상황, 단원별 작업 중인 회로·코드, 부품함을 브라우저 저장소에 저장한다(용량이 작으므로 `localStorage`로 시작). 읽기·쓰기 실패는 잡아서 앱이 죽지 않게 한다.
- 저장 데이터와 백업 파일에는 스키마 버전 번호를 넣는다. 형식이 바뀌면 순서대로 적용되는 마이그레이션 함수로 옮긴다. 마이그레이션마다 이전 버전 샘플 데이터로 테스트한다.
- 단원 id(`"1-3"` 등)와 부품 id는 한 번 배포하면 바꾸지 않는다. 진행 기록이 이 id에 묶여 있기 때문이다. 단원을 추가할 때는 새 id를 붙인다.
- 서비스 워커 업데이트 흐름: 새 버전을 받으면 바로 바꾸지 않고 "새 버전이 있어요 · 새로고침" 배너를 띄운다. 단원을 진행하는 도중에 화면이 갑자기 바뀌지 않게 하려는 것이다. 업데이트를 적용하기 전에 자동으로 로컬 백업을 하나 남긴다.

## 7. 마일스톤 (1차 범위)
1. **뼈대**: Vite 프로젝트, PWA(오프라인 캐시), 홈 화면, 단원 진행 흐름, 퀴즈, 저장/백업, GitHub Pages 배포 → 폰에서 열어 오프라인 동작 확인.
2. **전기 회로 해석기 + 회로 편집기 + 0장** (0-6은 게이트 기호로 넘어가는 다리 단원).
3. **디지털 시뮬레이터 + 커스텀 부품 + 1장 그리기 과제**.
4. **Verilog 해석기 + 1-5 이후 Verilog 과제**.
5. **순차 회로(래치, 클럭, 플립플롭, 타임라인 테스트) + 2장**.

마일스톤마다 폰에서 실제로 공부할 수 있는 상태로 배포한다. 사용자는 첫 배포부터 0장 공부를 시작할 수 있다.
2027년 초까지 필수 완료는 마일스톤 1~4다. 마일스톤 5(2장)는 그 전에 가능한 만큼 진행하고, 나머지는 이후 업데이트로 추가한다. 일정이 밀리면 단원을 추가하는 것보다 이미 배포한 단원의 검증을 먼저 한다.

## 8. 검증
- 시뮬레이터 3종은 각각 단위 테스트를 둔다. 예: 옴의 법칙, LED 구간 선형 수렴, SR 래치 유지, 논블로킹 대입 의미, 파서 오류 위치.
- **모든 단원의 모범 답안은 자기 채점기를 통과해야 한다.** 이 검사는 테스트로 자동화한다.
- 각 단원에 대표적인 오답 1개 이상을 넣고, 그 오답이 채점에서 **떨어지는지** 확인한다(실패 조건 "틀린 회로 통과" 방지).
- 폰 크기 화면에서 편집기 조작을 확인한다.
- 단원 내용의 기술적 사실은 일반 교과 수준으로 쓰고, 근거가 불확실한 구체적 제품 정보(특정 회사의 회로 등)는 넣지 않는다.

- 파일 세부 구조, 내부 API 이름, 서비스 워커 구현 방식(직접 작성 또는 작은 플러그인).
- 그림·아이콘·색상 등 시각 디자인. 단, 원본 게임과 닮지 않게 독자적으로 한다.
- 단원 본문 작성(Claude가 쓰고, 사용자가 학습자로서 읽으며 피드백).
